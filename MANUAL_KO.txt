1. 이 매뉴얼의 목적
================================================================================

이 매뉴얼은 Pepforge를 처음 사용하는 사람이 프로그램을 설치하고, 각 기능을 실행하고, 결과를 해석하고, GitHub 공개 및 학술적 인용까지 이어갈 수 있도록 작성한 실사용 설명서이다.

Pepforge는 단순한 peptide sequence generator가 아니라, peptide research workflow를 하나로 묶기 위한 도구이다. 따라서 이 매뉴얼은 단순 버튼 설명만 하는 것이 아니라 다음 내용을 함께 설명한다.

- 어떤 입력을 넣어야 하는가
- 어떤 기능을 어떤 순서로 써야 하는가
- 결과값은 어떻게 해석해야 하는가
- SPPS material 계산값은 어떤 의미인가
- Docking Workbench의 Delta G와 Kd는 어떤 수준의 값인가
- D-form, non-natural amino acid, linker, chemical이 들어간 peptide를 어떻게 다루는가
- output folder는 어떻게 관리하는가
- 논문, 발표, 보고서, 포트폴리오에서 Pepforge를 어떻게 인용해야 하는가

이 매뉴얼은 peptide chemistry, SPPS, docking, molecular dynamics 전체를 이론적으로 완전히 설명하는 교과서는 아니다. 대신 Pepforge를 실제로 사용하면서 사용자가 헷갈릴 수 있는 부분을 최대한 구체적으로 풀어 설명하는 것을 목표로 한다.


================================================================================
2. Pepforge란 무엇인가
================================================================================

Pepforge는 peptide 연구를 위한 통합 research workbench이다.

일반적인 peptide 연구에서는 다음 단계들이 서로 분리되어 있는 경우가 많다.

1. Target 또는 peptide sequence 분석
2. Hotspot 또는 motif 후보 탐색
3. Peptide 후보 생성
4. 합성 가능성 검토
5. SPPS reagent 및 solvent 계산
6. Target-peptide contact 분석
7. Docking-like screening
8. Molecular dynamics validation 준비
9. 결과 정리 및 citation

Pepforge는 이 흐름을 하나의 프로그램 안에서 가능한 한 자연스럽게 연결하려는 목적으로 만들어졌다.

즉, Pepforge의 핵심 질문은 다음과 같다.

- 이 peptide 후보는 서열상 의미가 있는가?
- 이 peptide 후보는 SPPS로 합성 가능한가?
- N-terminal 또는 C-terminal modification이 화학적으로 말이 되는가?
- Ac, NH2, D-form, non-natural amino acid, linker, label이 제대로 인식되는가?
- 실제 합성할 때 필요한 amino acid, reagent, solvent는 어느 정도인가?
- Target과 peptide 사이에 어떤 residue contact가 생기는가?
- 추정 Delta G와 Kd는 어느 정도이며, 후보 비교에 사용할 수 있는가?
- 외부 all-atom MD나 실험 검증으로 넘길 수 있는 output이 생성되는가?
- 학술 작업에 사용할 경우 citation이 보존되는가?

Pepforge는 이러한 질문들을 한 번에 다루기 위해 만든 peptide research support tool이다.


================================================================================
3. Pepforge가 아닌 것
================================================================================

Pepforge는 다음을 대체하지 않는다.

- 실제 peptide 합성 실험
- HPLC 정제
- LC-MS 또는 MALDI-TOF 확인
- SPR, ITC, MST, ELISA 등의 결합 실험
- 세포 실험
- cryo-EM, NMR, X-ray crystallography
- full all-atom molecular dynamics
- AutoDock Vina, PRODIGY, GROMACS, AMBER, NAMD 같은 전문 외부 도구
- 실험적으로 검증된 binding affinity
- 임상적 의사결정

Pepforge의 docking 및 molecular dynamics 관련 결과는 screening 및 triage 목적이다. 프로그램에서 Delta G와 Kd를 출력하더라도, 이는 실험값이 아니라 내부 contact-based estimate이다.

따라서 Pepforge 결과를 논문이나 최종 연구 주장에 사용할 경우, 외부 all-atom MD, docking server, 또는 실험적 검증이 필요하다.


================================================================================
4. 권장 사용 흐름
================================================================================

Pepforge를 사용하는 권장 순서는 다음과 같다.

1단계. Target 정보 준비
    Target protein sequence, FASTA, PDB, mmCIF 중 하나를 준비한다.

2단계. Hotspot 후보 확인
    Hotspot Finder를 사용하여 interaction에 중요할 가능성이 있는 residue 또는 motif 후보를 확인한다.

3단계. Peptide 후보 생성 또는 평가
    Peptide Design Engine을 사용하여 candidate peptide를 생성하거나 기존 후보를 평가한다.

4단계. SPPS 가능성 확인
    SPPS-aware filter를 통해 합성상 문제가 큰 후보를 거른다.

5단계. 합성 계획 수립
    SPPS Planner를 사용하여 synthesis plan, material usage, checklist를 만든다.

6단계. 구조 기반 screening
    Docking Workbench를 사용하여 target-peptide contact, estimated Delta G, estimated Kd, interaction class를 확인한다.

7단계. 결과 export
    CSV, PDB, citation notice, validation package 등을 output folder로 저장한다.

8단계. 외부 검증
    실제 논문급 affinity 또는 구조 검증이 필요하면 GROMACS, AMBER, NAMD, PRODIGY, 실험 검증으로 이어간다.

9단계. Citation
    Pepforge를 사용한 결과가 보고서, 논문, 학위논문, 포스터, 발표, 소프트웨어에 들어간다면 repository와 release를 인용한다.

5. 설치 및 첫 실행
================================================================================

권장 환경:

- Windows 10 또는 Windows 11
- Python 3.10 이상
- pip
- Git 또는 GitHub Desktop
- 가능하면 virtual environment 사용

기본 설치 방법:

1. GitHub에서 Pepforge repository를 clone하거나 ZIP을 다운로드한다.
2. Pepforge 폴더에서 터미널을 연다.
3. 필요한 패키지를 설치한다.

명령어:

    pip install -r requirements.txt

실행:

    python main_launcher.py

Python이 여러 개 설치되어 있으면 다음 명령어가 더 잘 동작할 수 있다.

    py main_launcher.py

개별 모듈 실행 예시:

    python main_launcher.py --tool design
    python main_launcher.py --tool spps
    python main_launcher.py --tool docking

실행 오류가 발생하면 다음 폴더를 확인한다.

    outputs/runtime_logs/

이 폴더에는 런타임 에러 로그가 저장될 수 있다.

7. Main Launcher
================================================================================

Main Launcher는 Pepforge의 시작 화면이다.

일반적으로 다음 기능을 실행할 수 있다.

- Hotspot Finder
- Peptide Design Engine
- SPPS Planner
- Docking Workbench

권장 사용법:

1. main_launcher.py를 실행한다.
2. 필요한 모듈을 선택한다.
3. 모듈 작업을 마친 뒤 닫는다.
4. 다시 Launcher에서 다른 모듈을 실행한다.

문제가 발생할 경우:

- Python dependency가 설치되어 있는지 확인한다.
- 터미널에서 실행하여 error message를 확인한다.
- outputs/runtime_logs/ 폴더를 확인한다.
- 개별 실행 옵션을 사용한다.

예시:

    python main_launcher.py --tool spps


================================================================================
8. Hotspot Finder
================================================================================

Hotspot Finder는 sequence 기반으로 중요 후보 위치를 탐색하는 모듈이다.

입력 가능한 것:

- protein sequence
- peptide sequence
- FASTA 형식 sequence

예시:

    >Target
    MSEQNNTEMTFQIQRIYTKDISFEAPNAPHVFQKDW...

출력 예시:

- hotspot position
- residue score
- ranking
- candidate region

해석 방법:

Hotspot score가 높다고 해서 해당 residue가 실험적으로 반드시 중요한 것은 아니다. Hotspot Finder는 mutation 실험이나 구조 실험을 대체하지 않는다.

권장 사용:

- peptide motif 후보 찾기
- target sequence에서 중요한 부분 추정
- design 시작점 정하기
- Peptide Design Engine에 넣을 motif 또는 region 선정

비권장 사용:

- hotspot score만으로 binding site 확정
- 실험 검증 없이 논문에서 결정적 근거로 사용


================================================================================
9. Peptide Design Engine
================================================================================

Peptide Design Engine은 peptide 후보를 생성하거나 평가하는 모듈이다.

주요 목적:

- peptide candidate 생성
- motif 기반 candidate 생성
- D-form 또는 non-natural residue 고려
- linker 또는 chemical modification 고려
- SPPS 가능성 필터링
- candidate ranking
- output CSV 저장

입력할 수 있는 정보:

- target sequence
- peptide length
- fixed motif
- allowed amino acids
- D-form 사용 여부
- non-natural amino acid 사용 여부
- linker 사용 여부
- terminal modification
- SPPS filter 설정

중요 output column:

SPPS_status
    PASS 또는 FAIL로 표시된다.

SPPS_reason
    왜 통과했는지 또는 왜 거절되었는지를 설명한다.

Nterm_available
    N-terminal free amine이 남아 있는지 여부이다.

Cterm_mode
    C-terminal acid, amide 등의 상태를 나타낸다.

modification_validity
    modification logic이 내부 규칙상 타당한지 표시한다.

중요 개념:

Peptide Design Engine은 단순히 점수가 높은 peptide를 만드는 것이 아니라, 실제 SPPS에서 문제가 적은 후보를 우선적으로 남기도록 설계되어야 한다.

예를 들어 N-terminus가 Ac로 막혀 있으면 N-terminal amine-dependent modification은 추가로 붙일 수 없다고 보는 것이 일반적이다. 이런 후보는 flag 또는 rejection 대상이 된다.


================================================================================
10. SPPS Planner
================================================================================

SPPS Planner는 solid-phase peptide synthesis 계획을 세우는 모듈이다.

주요 기능:

- peptide sequence 기반 synthesis plan 생성
- amino acid usage 계산
- reagent/base/catalyst usage 계산
- solvent usage 계산
- checklist 생성
- log 기록
- output folder export
- 이전 output folder load

화면 구성:

Project
    프로젝트 이름과 sequence 입력 영역이다.

Resin / Coupling / Base / Solvent Defaults
    resin, scale, loading, coupling reagent, base, solvent, deprotection 조건을 설정한다.

Branch mode / side-chain arm
    branched peptide 또는 side-chain modification을 설정할 수 있다.

Plan
    단계별 합성 계획을 보여준다.

Materials
    material usage를 category별로 보여준다.

Project
    project metadata를 보여준다.

Checklist
    실험 진행 체크리스트를 보여준다.

Log
    계산 또는 작업 기록을 보여준다.

주요 버튼:

Build/Rebuild
    현재 입력 조건으로 plan과 material table을 새로 만든다.

Load Project
    저장된 project를 불러온다.

Load Output
    이전 output folder를 불러온다.

Recalculate
    수정된 plan을 기반으로 다시 계산한다.

Export
    현재 결과를 output folder로 저장한다.

Materials tab의 보기 버튼:

Step full
    Step Material Usage table을 크게 보여준다.

AA full
    Amino Acid / Unit Usage table을 크게 보여준다.

Reagent full
    Reagent / Base / Catalyst Usage table을 크게 보여준다.

Solvent full
    Solvent Usage table을 크게 보여준다.

Balanced
    여러 material table을 균형 있게 다시 보여준다.

실제 사용 흐름:

1. Sequence에 peptide를 입력한다.
2. Resin type/family를 선택한다.
3. Resin scale을 입력한다.
4. Loading 값을 입력한다.
5. Coupling reagent와 catalyst/additive를 확인한다.
6. Deprotection 조건을 확인한다.
7. Build/Rebuild를 누른다.
8. Plan tab에서 step을 확인한다.
9. Materials tab에서 사용량을 확인한다.
10. Checklist tab에서 실험 진행표를 확인한다.
11. Export를 눌러 output folder를 생성한다.

예시:

Sequence:
    Ac-EEMQRR-NH2

Resin:
    Amide

Scale:
    400 mmol

Loading:
    0.8 mmol/g

Coupling reagent:
    DIC

Catalyst/Additive:
    HOBt

Deprotection:
    20 percent piperidine in DMF

주의:

SPPS Planner의 material usage는 planning estimate이다. 실제 실험에서는 resin swelling, peptide hydrophobicity, coupling efficiency, vessel volume, wash protocol, lab-specific SOP에 따라 조정이 필요하다.

11. Docking and Molecular Dynamics Workbench
================================================================================

Docking Workbench는 target-peptide interaction을 screening하는 모듈이다.

탭 구조:

1. Input
2. Results
3. Contacts
4. Molecular Dynamics
5. Export / Import

기본 흐름:

1. Target 입력
2. Peptide 입력
3. Analyze 클릭
4. Run 클릭
5. Results 확인
6. Contacts 확인
7. Molecular Dynamics 확인
8. Export 실행

입력 가능한 target:

- protein sequence
- FASTA
- PDB
- mmCIF

입력 가능한 peptide:

- peptide sequence
- modified peptide notation
- peptide PDB

예시 peptide:

    Ac-EEMQRR-NH2

또는 alias:

    AHP-8

AHP-8은 다음과 같이 해석된다.

    Ac-EEMQRR-NH2

Terminal state:

N-terminal:
    Ac

Core sequence:
    EEMQRR

C-terminal:
    NH2

중요:

PDB 파일에는 Ac 또는 NH2 terminal cap 정보가 명확하게 들어 있지 않을 수 있다. 이 경우 Pepforge는 사용자가 입력한 peptide notation에서 terminal metadata를 보존하려고 한다.

Analyze 버튼:

- 입력이 sequence인지 PDB인지 확인한다.
- peptide terminal state를 확인한다.
- D-form, non-natural residue, linker, chemical token을 분류한다.
- workflow 가능성을 점검한다.

Run 버튼:

- Analyze
- docking-oriented screening
- affinity report
- contact analysis
- molecular dynamics screening

흐름을 한 번에 실행한다.


================================================================================
12. Peptide 표기법
================================================================================

Pepforge는 실험자가 실제로 사용하는 peptide notation을 최대한 보존하는 방향으로 설계되어 있다.

기본 peptide:

    EEMQRR

N-terminal acetylation과 C-terminal amidation이 있는 peptide:

    Ac-EEMQRR-NH2

의미:

- Ac: N-terminal acetylation
- EEMQRR: core peptide sequence
- NH2: C-terminal amidation

Alias:

    AHP-8

의미:

    AHP-8 = Ac-EEMQRR-NH2

D-form 예시:

    Ac-dK-EEMQRR-NH2

Linker 예시:

    Ac-EEMQRR-PEG2-NH2

Label 예시:

    FITC-EEMQRR-NH2

복합 modification 예시:

    Ac-dK-Aib-PEG2-FAM-R-NH2

주의:

모든 token이 all-atom force field에서 자동으로 지원되는 것은 아니다. Pepforge 내부에서는 가능한 범위에서 screening을 진행하지만, 외부 all-atom MD에서는 parameter가 필요할 수 있다.


================================================================================
13. D-form, non-natural amino acid, linker, chemical 표기
================================================================================

Pepforge는 다양한 peptide modification을 고려할 수 있도록 설계되었다.

Canonical amino acids:

    A, R, N, D, C, Q, E, G, H, I, L, K, M, F, P, S, T, W, Y, V

D-form residue 예시:

    dA, dR, dK, dE

Non-natural amino acid 예시:

    Aib, Nle, Orn, Cit, Hyp, Dab, Cha, Nal

Linker 예시:

    PEG2, PEG4, PEG8, Ahx, AEEA, bAla, gAla

Chemical label 또는 moiety 예시:

    FITC, FAM, TAMRA, Biotin, Pal, Myr, DOTA, NOTA

Terminal cap:

    Ac, NH2

처리 방식:

- canonical residue는 직접 처리한다.
- D-form residue는 D-form flag와 함께 screening에 반영한다.
- non-natural residue는 가능한 경우 surrogate property로 처리한다.
- linker는 flexible spacer로 처리한다.
- bulky label은 approximate chemical bead로 처리할 수 있다.
- unknown token은 review required로 표시될 수 있다.

중요:

D-form, non-natural amino acid, linker, chemical이 포함된 peptide는 외부 all-atom MD에서 parameterization이 필요할 수 있다.


================================================================================
14. Ac 및 NH2 terminal modification 처리
================================================================================

Ac-EEMQRR-NH2는 다음을 의미한다.

- N-terminal Ac cap
- core sequence EEMQRR
- C-terminal NH2 amidation

이것은 EEMQRR과 다르다.

EEMQRR은 terminal cap이 명시되지 않은 peptide이다.

왜 중요한가?

1. Ac는 N-terminal free amine을 막는다.
2. NH2는 C-terminal carboxylate가 아니라 amide 상태를 의미한다.
3. N-terminal free amine이 필요한 반응은 Ac-capped peptide에서는 불가능할 수 있다.
4. C-terminal state는 resin 선택과 최종 peptide 형태에 영향을 준다.

예시:

Ac-EEMQRR-NH2에서 N-terminal amine-dependent modification을 다시 붙이는 것은 일반적으로 맞지 않는다. 단, Lys side-chain 같은 별도 reactive handle이 명시되어 있다면 다른 logic으로 처리할 수 있다.


================================================================================
15. SPPS-aware design logic
================================================================================

SPPS-aware design은 computational score뿐 아니라 실제 합성 가능성을 고려하는 design 방식이다.

Pepforge는 다음 요소를 확인하거나 flag할 수 있다.

- peptide 길이
- hydrophobic burden
- aggregation risk
- Cys 개수 및 위치
- D-form 또는 non-natural residue 과다 사용
- linker 과다 사용
- bulky label 과다 사용
- N-terminal modification compatibility
- C-terminal resin compatibility
- protecting group 및 SPPS 조건

예시:

N-terminus가 이미 Ac로 막혀 있는데 N-terminal succinylation을 추가하려고 하면, N-terminal free amine이 없기 때문에 block 또는 warning이 필요하다.

또 다른 예시:

너무 많은 hydrophobic residue가 연속되면 synthesis, solubility, purification에서 문제가 될 수 있으므로 warning이 필요하다.


================================================================================
16. Material usage 계산 logic
================================================================================

SPPS Planner는 editable Plan을 기준으로 material usage를 계산한다.

기본 계산 개념:

planned_mmol = resin_scale_mmol x equivalent x repeat_count

gram 계산:

calculated_g = planned_mmol x MW / 1000

여기서:

- planned_mmol은 mmol
- MW는 g/mol
- calculated_g는 g

예시:

Resin scale:
    400 mmol

Amino acid equivalent:
    5 eq

Repeat count:
    1

planned_mmol:

    400 x 5 x 1 = 2000 mmol

MW가 648.77 g/mol이면:

    2000 x 648.77 / 1000 = 1297.54 g

Solvent 계산은 설정된 mL per mmol, wash count, step count에 따라 달라진다.

주의:

실제 실험에서는 scale 단위가 mmol인지 umol인지 반드시 확인해야 한다. 프로그램 입력 단위와 실제 실험 단위를 혼동하면 사용량이 크게 달라질 수 있다. 실험 전 반드시 연구자가 직접 검토해야 한다.


================================================================================
17. Docking input logic
================================================================================

Docking Workbench는 입력 조합을 자동으로 해석하려고 한다.

가능한 조합:

Target sequence + Peptide sequence
    Sequence 기반 screening 또는 구조 생성 준비에 사용한다.

Target sequence + Peptide PDB
    Target은 coarse 또는 외부 구조 생성이 필요하고, peptide PDB는 pose 후보로 보존한다.

Target PDB + Peptide sequence
    Target 구조를 기준으로 peptide를 approximate screening한다.

Target PDB + Peptide PDB
    가장 직접적인 structure-based contact analysis가 가능하다.

Complex PDB
    Target과 peptide chain이 같은 구조 파일에 있으면 chain을 구분하여 contact를 분석할 수 있다.

입력이 잘못 인식될 때 확인할 점:

- FASTA header가 올바른가?
- Sequence에 숫자나 공백이 섞여 있지 않은가?
- PDB 경로가 실제 파일 경로인가?
- peptide notation에서 Ac와 NH2가 올바르게 적혀 있는가?
- PDB chain ID가 존재하는가?



================================================================================
17A. Docking Workbench에서 modified peptide 처리 방식
================================================================================

Docking Workbench는 D-form residue, 일부 non-natural amino acid, linker, chemical label, lipid-like moiety, terminal cap이 포함된 peptide도 분석 흐름에서 유지하도록 설계되어 있다.

다만 이것은 모든 modified residue를 내부에서 완전한 all-atom parameter로 처리한다는 뜻은 아니다. Pepforge는 modified peptide를 **token-preserving, screening-level surrogate handling** 방식으로 처리한다.

이 방식의 목적은 다음과 같다.

1. modified peptide notation을 잃어버리지 않는다.
2. peptide에 D-form 또는 non-natural unit이 있다고 해서 workflow가 바로 끊기지 않게 한다.
3. contact 및 affinity-style screening을 가능한 범위에서 수행한다.
4. 외부 all-atom validation에 필요한 parameter 요구사항을 명확히 남긴다.

입력 예시:

    Ac-dK-Aib-PEG2-FAM-R-NH2
    FITC-dK-Ahx-EEMQRR-NH2
    Ac-E-dM-Q-Orn-R-NH2

내부 screening 해석 예시:

    dK
        Lysine 계열 side-chain 성질과 D-form flag를 함께 유지한다.
        전하 및 contact tendency를 보존하는 데 사용된다.
        외부 all-atom validation에서는 D-residue topology와 chirality 검토가 필요하다.

    dE
        Glutamate 계열 acidic side-chain 성질과 D-form flag를 함께 유지한다.
        외부 all-atom validation에서는 D-residue topology와 chirality 검토가 필요하다.

    Aib
        compact neutral non-natural residue로 근사 처리한다.
        외부 all-atom validation에서는 non-standard residue parameter가 필요할 수 있다.

    Orn
        Lys-like cationic side-chain으로 근사 처리한다.
        외부 all-atom validation에서는 custom topology가 필요할 수 있다.

    Cit
        polar neutral side-chain으로 근사 처리한다.
        외부 all-atom validation에서는 custom parameter가 필요할 수 있다.

    Nle
        hydrophobic aliphatic residue-like unit으로 근사 처리한다.
        외부 all-atom validation에서는 non-standard residue parameter가 필요할 수 있다.

    Hyp
        Pro-like constrained residue로 근사 처리한다.
        외부 all-atom validation에서는 별도 residue definition이 필요할 수 있다.

    PEG2 / PEG4 / PEG8
        flexible linker-like unit으로 처리한다.
        외부 all-atom validation에서는 linker topology가 필요하다.

    Ahx / AEEA
        flexible spacer-like unit으로 처리한다.
        외부 all-atom validation에서는 linker 또는 spacer parameter가 필요하다.

    FAM / FITC / TAMRA
        bulky aromatic 또는 fluorescent label-like unit으로 처리한다.
        외부 all-atom validation에서는 small-molecule 또는 dye parameter가 필요하다.

    Pal / Myr
        hydrophobic lipid-tail-like unit으로 처리한다.
        외부 all-atom validation에서는 lipid-like tail parameter가 필요하다.

    Ac
        N-terminal acetyl cap으로 처리한다.
        외부 all-atom validation에서는 terminal patch 처리가 필요할 수 있다.

    NH2
        C-terminal amide로 처리한다.
        외부 all-atom validation에서는 terminal patch 처리가 필요할 수 있다.

Docking Workbench에서 modified peptide에 대해 가능한 것:

- modified peptide notation parsing
- Ac 및 NH2 terminal metadata 보존
- D-form 및 non-natural token 분류
- linker 및 label token 보존
- contact-oriented screening
- residue/proxy contact report 생성
- estimated Delta G 및 Kd screening report 생성
- embedded molecular-dynamics screening
- 구조가 있거나 생성된 경우 best_docking_complex.pdb export
- contact_annotated_complex.pdb export
- token_parameter_requirements.csv export
- all_atom_validation_package export

내부에서 보장하지 않는 것:

- 모든 non-natural residue의 정확한 all-atom geometry
- 모든 modified token의 force-field-ready topology
- 모든 chemical label의 정확한 partial charge
- 실험값 수준의 Delta G 또는 Kd
- 외부 검증 없는 논문급 MD 정확도

권장 해석:

    Modified peptide workflow support:
        지원함.

    Screening-level contact 및 affinity estimation:
        지원함.

    Full all-atom quantitative accuracy:
        내부에서 보장하지 않음.

    External parameterization:
        D-form, non-natural, linker, label, lipid-like, unknown token에는 권장됨.

정리하면 Docking Workbench는 modified peptide workflow가 끊기지 않도록 설계되어 있다. 따라서 후보 비교, 1차 screening, contact 해석, validation package 준비에는 사용할 수 있다. 하지만 D-form 또는 non-natural residue가 포함된 peptide의 최종 정량적 결론을 내리려면 외부 all-atom parameterization 및 validation이 필요하다.


================================================================================
18. Affinity report 해석
================================================================================

Docking Workbench의 Results tab에는 affinity report가 표시된다.

주요 항목:

estimated_Delta_G 또는 estimated_ΔG
    추정 binding free energy이다.
    단위는 kcal/mol이다.

estimated_Kd
    추정 dissociation constant이다.
    값의 크기에 따라 nM, uM, mM, M 중 하나의 대표 단위로 표시된다.

interface_residue_contacts
    target과 peptide 사이 residue-level contact 수이다.

hydrogen_bond_contacts
    hydrogen-bond proxy contact 수이다.

hydrophobic_contacts
    hydrophobic contact 수이다.

charged_contacts
    charged 또는 salt-bridge-like contact 수이다.

steric_clashes
    너무 가까운 거리로 인한 clash 수이다.

minimum_distance
    가장 가까운 contact distance이다.
    단위는 Angstrom이다.

confidence
    정성적 confidence label이다.

method_scope
    이 결과가 screening estimate라는 점을 설명한다.

Delta G와 Kd 관계식:

    Delta G = RT ln(Kd)
    Kd = exp(Delta G / RT)

상수:

    R = 0.001987204 kcal mol^-1 K^-1
    T = 298.15 K

중요:

Pepforge의 Delta G는 실험값이 아니다. 내부 contact-based score를 일반적으로 통용되는 Delta G/Kd 형식으로 변환한 screening estimate이다.

해석 기준:

- Delta G가 더 음수일수록 결합이 강한 후보로 해석할 수 있다.
- Kd가 낮을수록 결합이 강한 후보로 해석할 수 있다.
- Contact 수가 많고 clash가 적으면 일반적으로 더 좋은 후보일 수 있다.
- 그러나 최종 결론은 외부 검증이 필요하다.


================================================================================
19. Contact analysis 해석
================================================================================

Contacts tab은 target과 peptide의 상호작용을 보여준다.

주요 표:

Residue contacts
    residue-level interaction을 보여준다.

Atom contacts
    atom-level 또는 proxy atom-level contact를 보여준다.

Peptide residue map
    peptide position과 residue class를 보여준다.

Residue label 예시:

    4Q

의미:

    peptide 4번 residue가 Q라는 뜻이다.

Target label 예시:

    A:134D

의미:

    target chain A의 134번 residue가 D라는 뜻이다.

상호작용 class:

contact
    일반 contact이다.

hydrogen_bond_proxy
    hydrogen bond 가능성이 있는 heavy atom distance 기반 proxy contact이다.

hydrophobic
    소수성 contact이다.

salt_bridge_like
    전하 상호작용 또는 salt bridge 가능성이 있는 contact이다.

clash_or_covalent_range
    너무 가까운 거리로 인해 steric clash 또는 비현실적 geometry 가능성이 있는 contact이다.

거리 기준:

hydrogen-bond donor-acceptor proxy:
    약 3.9 Angstrom

hydrophobic contact:
    약 5.0 Angstrom

generic interface contact:
    약 5.0 Angstrom

steric clash:
    약 2.0 Angstrom

주의:

PDB 파일에 hydrogen atom이 없으면 정확한 hydrogen bond angle을 판단할 수 없다. 따라서 Pepforge는 hydrogen_bond_proxy라는 표현을 사용한다.


================================================================================
20. Molecular dynamics screening 해석
================================================================================

Pepforge에는 embedded molecular dynamics screening이 포함되어 있다.

이 기능은 full all-atom MD가 아니다. 내부적으로 빠르게 pose 안정성, contact persistence, clash tendency 등을 확인하기 위한 lightweight screening이다.

주요 항목:

RMSD
    구조 변화 정도를 나타내는 지표이다.

contact_count
    유지되는 contact 수이다.

clash_count
    문제가 되는 너무 가까운 contact 수이다.

energy_proxy
    내부 energy-like score이다.

contact_persistence
    contact가 screening 과정에서 얼마나 유지되는지 나타낸다.

해석:

- RMSD가 낮으면 pose가 상대적으로 안정적일 수 있다.
- contact persistence가 높으면 contact가 유지되는 경향이 있다는 뜻이다.
- clash_count가 높으면 pose가 좋지 않을 수 있다.
- 이 결과는 screening 용도이며, 논문급 MD 결과를 대체하지 않는다.

예시 1. AHP-8의 SPPS planning
--------------------------------------------------------------------------------

목표:
    AHP-8 peptide의 SPPS material usage를 계산한다.

Peptide:

    AHP-8 = Ac-EEMQRR-NH2

실행:

1. Pepforge를 실행한다.
2. SPPS Planner를 연다.
3. Sequence에 입력한다.

    Ac-EEMQRR-NH2

4. Resin family를 Amide로 선택한다.
5. Resin scale을 입력한다.

    400 mmol

6. Loading을 입력한다.

    0.8 mmol/g

7. Coupling reagent를 확인한다.

    DIC

8. Catalyst/additive를 확인한다.

    HOBt

9. Deprotection 조건을 확인한다.

    Piperidine, 20 percent in DMF

10. Build/Rebuild를 누른다.
11. Plan tab을 확인한다.
12. Materials tab을 연다.
13. AA full, Reagent full, Solvent full을 눌러 category별 사용량을 확인한다.
14. Export를 누른다.
15. Output folder를 확인한다.

해석:

Material table은 planning estimate이다. 실제 실험에서는 scale, vessel, resin swelling, peptide hydrophobicity, protecting group, lab SOP에 따라 조정해야 한다.

--------------------------------------------------------------------------------
예시 2. AHP-8과 YKT6 receptor의 Docking Workbench screening
--------------------------------------------------------------------------------

목표:
    AHP-8과 Synaptobrevin homolog YKT6 receptor의 contact 가능성을 screening한다.

Target:

    Synaptobrevin homolog YKT6 sequence 또는 PDB

Peptide:

    AHP-8

또는:

    Ac-EEMQRR-NH2

실행:

1. Docking Workbench를 연다.
2. Input tab에서 target sequence 또는 PDB를 넣는다.
3. Peptide input에 AHP-8을 입력한다.
4. Analyze를 누른다.
5. Terminal state를 확인한다.

    N-terminal = Ac
    Core = EEMQRR
    C-terminal = NH2

6. Run을 누른다.
7. Results tab을 확인한다.
8. estimated Delta G와 estimated Kd를 확인한다.
9. Contacts tab을 연다.
10. 4Q -> A:134D 같은 residue contact를 확인한다.
11. Molecular Dynamics tab에서 screening 결과를 확인한다.
12. Export를 누른다.
13. best_docking_complex.pdb와 contact_annotated_complex.pdb를 확인한다.

해석:

결과는 screening estimate이다. 실제 binding claim을 하려면 외부 all-atom MD 또는 실험 검증이 필요하다.

--------------------------------------------------------------------------------
예시 3. D-form 및 non-natural amino acid 포함 peptide
--------------------------------------------------------------------------------

입력:

    Ac-dK-Aib-PEG2-FAM-R-NH2

의미:

- Ac: N-terminal cap
- dK: D-form lysine
- Aib: non-natural amino acid
- PEG2: linker
- FAM: fluorescent label
- R: arginine
- NH2: C-terminal amidation

Pepforge 내부 처리:

- dK는 D-form residue로 표시된다.
- Aib는 non-natural residue로 표시된다.
- PEG2는 linker로 표시된다.
- FAM은 chemical label로 표시된다.
- NH2는 C-terminal amide로 표시된다.

주의:

외부 all-atom MD에서는 dK, Aib, PEG2, FAM 각각의 parameter가 필요할 수 있다.

28. 한계점
================================================================================

Pepforge의 한계는 명확히 이해해야 한다.

과학적 한계:

- estimated Delta G는 실험값이 아니다.
- estimated Kd는 실험값이 아니다.
- contact-based score는 approximate이다.
- embedded MD screening은 full all-atom MD가 아니다.
- non-natural residue는 외부 parameter가 필요할 수 있다.
- SPPS material usage는 planning estimate이다.
- 실제 합성 조건은 실험실마다 다르다.

소프트웨어적 한계:

- 입력 형식이 너무 복잡하면 사용자가 직접 정리해야 할 수 있다.
- PDB 파일에 terminal cap 정보가 없을 수 있다.
- chain ID 인식은 사용자가 검토해야 할 수 있다.
- 매우 큰 구조는 느릴 수 있다.
- unknown token은 approximate 처리될 수 있다.

사용자 책임:

Pepforge output은 연구자의 판단을 대체하지 않는다. 실험 전, 논문 작성 전, 외부 공유 전에는 반드시 사용자가 직접 검토해야 한다.

================================================================================
30. 최종 정리
================================================================================

Pepforge는 peptide design, SPPS planning, docking-oriented screening, contact analysis, molecular dynamics validation bridging을 연결하기 위한 public research workbench이다.

가장 강력한 사용 방식은 Pepforge를 black-box predictor로 쓰는 것이 아니라, 연구 흐름을 정리하고 후보를 비교하고 합성 계획을 세우고 외부 검증으로 이어가는 workbench로 사용하는 것이다.

Pepforge는 다음을 돕는다.

- peptide 후보 생성
- 합성 가능성 검토
- SPPS material planning
- terminal modification 확인
- D-form 및 non-natural token 보존
- docking-oriented contact screening
- estimated Delta G/Kd report
- PDB export
- all-atom validation package export
- output folder 기반 결과 관리
- citation 보존

학술 작업에 Pepforge를 사용했다면 repository와 release를 인용해야 한다.
